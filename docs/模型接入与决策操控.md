# 模型接入与决策操控

2026-10-23：按用户本轮授权，增加模型设置与参考 jev-ultrafast 的浏览器任务。最初先做本地模拟验收；10 月 23 日随后按用户授权接入真实 Jev 象棋验证，结果单独记录。本地模拟服务只能验证接入、控制流程，不能证明真实模型的能力或时延。继续限定 macOS ARM64 第一阶段。

## 设置

打开 **设置 → 模型与浏览器任务**（`chrome://settings/ai`）。

1. 添加服务商，选择预设后直接填写 API Key。预设只包含名称、URL 和协议，不内置固定模型清单。国内与国际入口分别列出。
2. 自建网关勾选 **Custom**，预设选择随即禁用；填写名称、协议、URL 和 Key。可添加多个独立配置。
3. URL 缺省补 `https://`；明确填写 `http://` 时保留。根地址补 `/v1/`，已有 `/v1` 补末尾斜杠；保留 `/v1beta/`、`/api/paas/v4/` 等显式路径。
4. 字段填写完整后自动获取服务端模型列表，按服务端分页取完并去重。选择模型后发起一次小型调用测试；也可手动刷新列表、重新测试。
5. 绿点只表示该配置最后选择的模型调用成功，不表示清单中的每个模型均可用。换地址、密钥、协议或模型后，旧验证状态失效。接口报错、空列表和不支持模型枚举会明确显示，不拿预设清单补齐。

动态获取到的列表会保存在当前 Profile，重新打开仍可选择；刷新以最新服务端结果替换。API 返回的模型可能包括图像、音频、嵌入模型，这些也保留在列表中，但本轮调用测试及文字辅助只支持所选协议的文本输出，不宣称适配全部模型能力。列表最多 100 页、每响应 4 MiB；达到限制会报“不完整”，不视为取完。

预设共 32 个入口：OpenAI、Anthropic、Google Gemini、OpenRouter、DeepSeek、xAI、Mistral、Groq、Together、Fireworks、Cerebras、Qwen（国际／中国）、Kimi（国际／中国）、Z.AI／智谱、SiliconFlow（国际／中国）、MiniMax（国际／中国）、StepFun、NVIDIA NIM、Doubao、Baidu Qianfan、Tencent TokenHub、Xiaomi MiMo、ModelScope、Hugging Face、AiHubMix、Poe、TypeSafe Jev。预设地址来自官方源码中的服务商登记；并非已经逐家持有密钥验证。

支持 OpenAI Chat、OpenAI Responses、Anthropic Messages、Gemini generateContent、TypeSafe System One 五种协议。OAuth 订阅登录、AWS IAM、Azure 私有部署、自动识别网关协议不在本轮范围。需要部署专属地址时使用 Custom。

Key 经 Chromium OSCryptAsync 加密后写入当前 Profile 的 Preferences，使用系统凭据保护；不写入仓库、连接二维码或日志，也不回传设置页。请求由浏览器原生层发出，不带网站 Cookie；只向用户配置的同一 API 地址下的协议端点发送，拒绝重定向携带密钥。

## 浏览器任务

配置并测试一个 TypeSafe 决策模型；需要填写文字时再选择一个通用模型。在同一页面选择空闲的非主空间，输入目标，点击“开始”。请让设置页保持打开。

- 观察：读取目标空间当前页面的可访问性树，形成带索引的控件与页面文本。
- 决策：一次 Jev 请求同时判断操作及对应控件。模型只能选择观察结果中已有的选项，不生成选择器、JS 或任意坐标。
- 输入：需要填字时，通用模型返回单字段 JSON；校验后才填写。
- 执行：重新观察并检查控制权、当前标签及页面状态；过期决策丢弃。复用原生租约和 `snapshot/clickRef/fillRef/scroll` 接口，不开放全局 CDP。
- 接管：人或 VNC 接管后暂停；原任务收到交还后取得新租约，重新观察再继续。停止、关闭设置标签或导航到非设置页面会释放该任务自己的控制权。

通用任务最多 60 轮决策；象棋任务最多确认成功 60 步，异常选项最多重试一次。网络请求串行，30 秒超时。界面显示执行步数和实际耗时。完成提示是“模型判断完成”，不是独立质量验收结论。

通用任务支持点击、填写、滚动、等待、结束／无法继续，继续采用页面元素驱动。新增的象棋路径通过空间截图读取渲染后的棋盘；通用 Canvas/WebGL 游戏、跨域 iframe 完整模型操作、任意下拉选择和长期后台任务不在已支持范围。已有 MCP/VNC 能力保持原样，主空间仍仅人操作。

## Jev 象棋快速路径

1. 在一个非主空间打开 [Xiangqi 人机对战](https://play.xiangqi.com/computer)，选择先后手和电脑等级，点击“对弈”，确认进入 `/computer-play` 棋盘。
2. 在设置页选择已测试通过的 TypeSafe Jev、该任务空间，目标填“下中国象棋”。下棋不需要选择文字模型。保持设置标签打开，可以切到棋盘观察、接管、交还，或回设置页停止。
3. 象棋目标只进入电脑对局适配器；若还在准备页或跳到其他页面，明确停止，不回退到通用点击循环。

每步读取可见 DOM 中的棋子、交叉点、步数与选中状态，将棋盘裁剪为最长边 512 px、JPEG 质量 70。当前棋盘图片为 448×512，实测一张约 44.9 KB，原生抓图约 10 ms（单次样本）。请求通过 TypeSafe 原生 `/v1/systemone`、`assets` 和 `TypeSafe-Danger-Zone-Images: true` 发送，不经 OpenAI 兼容协议，也不传整个桌面。

本地代码只枚举合法走法，包括马腿、炮架、过河、九宫及将帅安全；不做棋力搜索、不调用棋类引擎、不读取网站内部引擎或 React 状态。每步由 Jev 从完整合法走法中选一个，选中棋子后回读，再点击落点，确认页面步数和棋盘变化后才计为成功。动画、页面布局变化或租约过期时重新观察。显示单步总耗时、Jev 请求耗时、抓图与局面准备耗时及累计平均值；总耗时不含等待对手思考。

官方参考：[实时应用案例](https://docs.typesafe.ai/concepts/use-case-map)、[图像输入](https://docs.typesafe.ai/images)、[Jev 1.14 实验功能](https://typesafe.ai/blog/jev-1-14)。图像能力仍是官方实验功能；跑通连续落子与具有稳定高棋力是两项不同验收。

### 2026-10-23 真实 Jev 象棋验证

使用用户已配置的 `jev-latest`，在 Xiangqi 的电脑 Level 1 对局执红。Computer Use 直接观察到连续 18 步、电脑回复，以及接管时棋局停在第 36 半回合；交还后继续到第 38 半回合。随后后台读取到第 120 半回合和已释放的空间控制权，达到本轮 60 步上限。没有用模拟模型或棋类引擎替 Jev 选招。

界面记录的前 14 步平均耗时为 856 ms/步；第 9 步 818 ms（Jev 请求 352 ms、抓图与局面准备 12 ms），第 14 步 843 ms（Jev 请求 373 ms、抓图与局面准备 14 ms）。这是本机、当前网络及该局的样本，排除了等待电脑思考和人工暂停，不是完整 60 步的平均值、P95 或最快性能保证。

修正了棋子动画期间重复读取、源棋子尚未选中便点击落点的问题；目标是象棋但页面不在 `/computer-play` 时现在明确停止，避免准备页退回通用循环后误入其他对局。连续落子、控制权交接已验证；赢棋率、执黑路径和其他棋类网站没有列入本轮验收。
